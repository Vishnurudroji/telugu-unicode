Telugu Vector Studio

From Legacy Telugu Typing to Modern Publishing

A browser-based Telugu text conversion application designed to bridge the gap between legacy ANU6/ANU7 encoding systems and modern Unicode publishing workflows.

ANU6 / ANU7 Unicode Conversion JavaScript Rule-Based Engine Local Processing
PROJECT AT A GLANCE

Reusing legacy Telugu content in modern publishing applications.

Solution

Convert ANU6/ANU7 text into standard Unicode and back.

Dictionary-based mapping with greedy longest-match processing.

02 / THE ORIGIN

How the Idea Started

Observing a real-world problem

The idea started by observing how Telugu typing and publishing work in DTP environments. Applications such as FlexiSIGN and CorelDRAW are used for creating banners, signboards, stickers, invitations and other printed materials.

Many older workflows depend on ANU-based keyboard layouts and compatible legacy fonts. When operators receive old Telugu content, reusing it in modern software can become difficult.

The problem identified

  • Existing legacy text may not behave like standard Unicode Telugu.
  • Operators may need compatible legacy fonts to view the content.
  • Re-entering old Telugu text creates repetitive work.
  • Manual typing can introduce spelling and character-combination mistakes.
  • Legacy content is harder to search and reuse in modern workflows.
The question that started the project:
Can we convert existing ANU Telugu text into Unicode automatically instead of asking users to type everything again?

Integrated the engine with a browser interface using HTML, CSS and JavaScript ES modules.

06

04 / THE SOLUTION

How It Solves the Problem

Earlier workflow

  1. Open old content using a compatible ANU font.
  2. Understand the legacy keyboard layout.
  3. Manually re-enter the Telugu content.
  4. Correct mistakes and adjust the design.

New workflow

Existing ANU7 Text→ Telugu Vector Studio→ Unicode Telugu→ FlexiSIGN
  1. Copy existing ANU7 text.
  2. Paste it into Telugu Vector Studio.
  3. Select ANU7 → Unicode and convert.
  4. Copy the Unicode result.
  5. Paste into FlexiSIGN or compatible software.
  6. Choose a compatible Telugu Unicode font.
  7. Edit and optionally convert text into vector outlines.
Important: Unicode text is editable text, not vector artwork. FlexiSIGN's text-to-outline or convert-to-curves functionality creates vector shapes for cutting workflows.
05 / SYSTEM DESIGN

System Architecture

User Input→ Application Logic→ Conversion Engine→ Mapping Lookup→ Output

Presentation Layer

HTML and CSS provide the interface, text editors, controls, conversion direction and result display.

Application Layer

JavaScript handles input, validates the selected mode, calls the engine, updates the interface and handles copying.

Processing Layer

The conversion engine performs normalization, Telugu sequence processing, mapping and output generation.

Mapping Data Layer

Structured mapping groups include base, vattu, gunintam, halant, ksha and ligature data.

Output Layer

Returns converted text for display, copying and use in external applications.

2. Greedy Longest-Match Algorithm

Telugu combinations may contain multiple components. The engine checks longer sequences before shorter sequences to avoid incorrectly splitting a valid combination.

  1. Start at the current input position.
  2. Check the longest eligible sequence.
  3. Search for a matching mapping entry.
  4. If found, append its converted value.
  5. Move past the matched sequence.
  6. If no match is found, apply fallback handling.
  7. Continue until the input is processed.

3. Reverse Lookup Using JavaScript Map

Reverse conversion uses a lookup structure that connects ANU code sequences to Unicode equivalents. The reverse mapping is cached to avoid rebuilding it for every conversion. 

const reverseMap = new Map();

for (const [unicode, anu] of Object.entries(mapping)) {
  reverseMap.set(anu, unicode);
}

This is a simplified illustration of reverse mapping, not the complete engine source.

4. Maximum Sequence Length

The engine tracks the maximum eligible mapping sequence length. This limits the number of candidate sequences checked at each input position.

5. Unicode NFC Normalization

const normalized = text.normalize("NFC");

NFC normalization creates a consistent canonical representation of Unicode input where applicable. It helps reduce mismatches between canonically equivalent sequences.

6. Heuristic Format Detection

The engine has a format detection function that uses heuristic scoring to estimate whether input resembles ANU6 or ANU7. This is an estimate, not guaranteed identification.

Reference comparison

Compares the converter's output with expected reference output. It measures agreement with the reference implementation.

Round-trip consistency

Converts Unicode to ANU and back to Unicode, then compares the final result with the original.

A successful round trip does not independently prove that the ANU representation is historically correct. These supplied evaluation results are distinct from the application's 32 built-in automated checks.

09 / KNOWN LIMITATIONS

Limitations

  • Legacy visual rendering depends on compatible ANU fonts.
  • Some legacy byte sequences can represent multiple Telugu sequences.
  • Some archaic Telugu characters have no corresponding legacy font glyph.
  • The converter processes text, not complete publishing documents.
  • Original document formatting, page layout, graphics and text positions are not preserved.
  • Unicode output still requires compatible font and shaping support in the target application.
  • The current 32 automated checks are not comprehensive coverage of all Telugu combinations.

12 / PROJECT OUTCOME

Conclusion

Telugu Vector Studio started with a practical observation: existing Telugu content should not have to be manually retyped simply because it is stored in an older encoding.

The project evolved through mapping analysis, conversion-engine development, reverse lookup, Unicode normalization and validation.

Its core engineering approach uses deterministic mapping tables, greedy longest-match processing, reverse lookup caching and structured Telugu character mappings.

The project also recognizes the limitations of legacy encoding. Some byte sequences are ambiguous, some characters are unsupported by older fonts, and not every conversion can be perfectly reversed.

Project vision:
Build a useful Telugu publishing toolkit that connects legacy content with modern editing, design and vector production workflows.

Convert existing Telugu content instead of typing it again.
13 / INTERVIEW PREPARATION

Explain the Project in an Interview

Tell me about your project.

Telugu Vector Studio is a browser-based Telugu text conversion application that converts legacy ANU6 and ANU7 text into standard Unicode and vice versa.

The idea came from observing the workflow of DTP operators and printing shops. They often work with legacy ANU fonts and keyboard layouts. When they need to reuse existing Telugu content in modern applications like FlexiSIGN or CorelDRAW, manually retyping the content takes time and can introduce errors.

I studied the Unicode-to-ANU mapping data and developed a rule-based conversion engine using dictionary-based mappings and greedy longest-match processing.

For reverse conversion, I implemented lookup mapping with caching. I also used Unicode NFC normalization to maintain consistent text representation.

The application is built using HTML, CSS and JavaScript ES modules. It performs conversion directly in the browser.

I evaluated the mappings using reference comparisons and round-trip tests, and documented cases where legacy byte ambiguity prevents exact recovery.
